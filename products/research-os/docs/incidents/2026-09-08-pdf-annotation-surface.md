# PDF 批注交互偏离原文定位要求

用户标注：chat / paper-temp，PDF 阅读与批注中的 textarea.ui-input。

判定：操作者要求直接标注原文，实际交付成页底固定表单，扭曲了批注的决策表面；缺少批注稳定身份也阻碍精确标注。此前只验证“保存记录、带入聊天”这条数据链，没有验收选区位置、公式/图表区域和批注在 PDF 上的回显。当前仓库没有覆盖这项交互约束的 canonical skill；仅凭数据链验收记录未能阻止偏差。

修正规约：文字批注保存原文及逐行归一化矩形；区域批注保存归一化矩形、区域内可提取文本和上下文。批注绑定 PDF digest、构建、源路径和页码。编辑器紧邻选区，保存标记直接覆在原文，版本切换不混用坐标。发送给聊天必须包含这些定位数据，不能声称它们是精确 LaTeX 源码行号。PDF 业务位于 features/resources；共享右栏只提供操作槽位。

验收必须覆盖选中文字、框选公式区域、保存后原位回显、缩放后定位、重载、版本隔离以及发送内容。禁止用只在页底显示的表单替代原文批注。

关联回归：聊天把通用错误和 disconnected 状态分别插入正文顶部，两条横栏移动操作区，违反单层顶栏约束。应在已有顶栏内提供稳定状态入口，详情按需展开，保留恢复操作，不掩盖失败。

根因证据：paper-temp 验证线程事件 126/128 为 Local host stopped，127/129 为 Host restarted；最近一轮 124 已 completed。断开来自服务重启，不能呈现为用户网络故障，也不能自动重发旧任务。
