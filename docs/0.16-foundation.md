# XGC2 UI 0.16 Foundation Reset

This branch establishes the visual and interaction foundation for the next XGC2 workbench generation.

## Goals

- Raise core primitives from functional/internally-consistent to product-quality.
- Preserve shared ownership: products own domain state and composition; shared UI owns visual language, interaction behavior, accessibility, and reusable workspace mechanics.
- Make the default visual language quieter, more legible, and more modern without turning XGC2 into a generic SaaS skin.
- Keep dense operator workflows efficient while improving typography, control geometry, focus clarity, and surface hierarchy.
- Prepare a stable base for Conversation, Workbench, Manuscript/PDF, Workflow, and other high-level packages.

## Foundation decisions

1. **Graphite/slate neutral base.** Dark mode uses neutral graphite surfaces instead of the previous warm brown cast. Light mode remains cool blue-grey.
2. **Readable compact typography.** Ordinary product content should not depend on 9–10 px type. The shared scale is shifted upward while remaining dense.
3. **Quiet surfaces.** Elevation comes primarily from luminance and spacing. Strong shadows are reserved for floating/overlay layers.
4. **32 px default controls.** Compact controls remain available for dense toolbars, but general-purpose interactive controls gain more breathing room.
5. **40 px page chrome.** Shell chrome is slightly more generous to stabilize navigation and future workbench composition.
6. **Short spatial motion.** New motion tokens are tuned for direct manipulation, with reduced-motion collapsing durations to zero.
7. **Progressive enhancement.** Newer CSS capabilities may be used when they degrade safely. Product correctness must never depend on a decorative browser feature.

## Quality bar

A primitive is not considered stable merely because it passes policy and unit tests. Stable components must also be visually reviewed in:

- dark and light modes,
- keyboard focus,
- hover/active/disabled states,
- compact and default density,
- desktop and compact viewport,
- long/empty/error content cases.

The gallery is the visual reference implementation for this review.

## Package direction

The shared system remains split by capability rather than becoming one large bundle:

- `@xgc2/ui-react`: foundation and common application primitives
- `@xgc2/ui-workflow`: spatial workflow interaction
- `@xgc2/ui-manuscript`: source/PDF research surfaces
- future `@xgc2/ui-conversation`: streaming human/agent interaction
- future `@xgc2/ui-workbench`: multi-resource editing and workspace composition

Heavy dependencies such as Monaco and PDF.js stay outside `@xgc2/ui-react`.
